Troubleshooting

CJW-Apps ITAM · Version 2.9.0 · For administrators

Find the message or problem you see. ITAM's error messages stay on screen until you press OK, and the last 20 are kept under the alert bell (Recent messages), so you can read them again.

Where to look first - itam.log, in ITAM's folder beside CJW_Apps_ITAM.exe (as a Windows service: C:\ProgramData\CJW-Apps-ITAM). - Change Log Ledger (left menu): every change, sign-in, lockout and scheduled run.

Starting ITAM

"Port 5050 is already in use" ITAM uses the next free port instead and opens it automatically. To choose a port yourself: Settings → Server & Access, then Restart.

Other computers cannot open ITAM Set Settings → Server & Access to 0.0.0.0 – other computers on your network, restart ITAM, and allow the network port (default 5443) through Windows Firewall on the ITAM PC. Others then open one of the addresses listed under Opening ITAM from other computers on that tab: they start with https://, for example https://192.168.1.20:5443. http:// addresses and port 5050 only work on the ITAM PC itself. If it worked before and stopped, the PC's IP address may have changed: use the PC's name instead, or ask for the address to be reserved. If the tab says in red that network access could not start, it says why (for example the network port is in use: choose another and restart).

"Your connection isn't private" (NET::ERR_CERT_AUTHORITY_INVALID) on another PC Expected with the certificate ITAM makes itself. Check the certificate's fingerprint in the browser matches the one in Settings → Server & Access, then choose Advanced → Continue. To stop the warning, install the certificate from Download certificate (.crt) on the other PCs (Trusted Root Certification Authorities), or import your company's certificate (PFX).

The fingerprint in the browser does not match Settings If that PC has an antivirus that inspects secure connections (for example Norton's Web Shield), it shows its own certificate instead: look at "Issued by" in the browser. Otherwise do not continue: you may not be talking to the ITAM PC.

Importing the company certificate fails The message says why: the password is wrong; the PFX has no private key (export it again with the private key); it has run out or is not valid yet; or it is not made for web servers (Server Authentication). A warning that the certificate does not name this PC means browsers will still complain: use the name or address it was issued for.

"CJW-Apps ITAM could not start" The message says why, usually that another program uses the network port (default 5443). Close that program and start ITAM again, or choose another Network port (HTTPS) in Settings → Server & Access and restart.

Closing the window did not stop ITAM That is by design: ITAM keeps running so backups and schedules still happen. To stop it, right-click the ITAM icon near the clock and choose Quit ITAM, or (built-in admin account) use Shutdown/Reset → Shut down.

Signing in

A button or tab is greyed out with a lock Your role does not include it. Hover over it to see which role is needed, and ask an administrator to change your role in Settings → Users & Auth (see Roles in the Setup guide). New accounts start as Viewer (read-only).

"This needs the Editor role or higher" / "This needs the Administrator role" The same: the action needs a higher role.

"Locked" after wrong passwords Five wrong passwords lock that username for 15 minutes; twenty from one address lock the address. Wait, or ask an administrator to Reset PW: a reset also lifts the lock.

The admin password is forgotten On the sign-in page, press Ctrl + Shift + Alt + R (or click the logo five times) and enter the Master Recovery Key. Without the key there is no way back in except restoring a backup.

Sign in with Microsoft

The sign-in page shows Microsoft's message. Find its code:

Code Meaning Fix
AADSTS50011 Redirect address does not match In Entra → your app → Authentication, add exactly the address ITAM shows (under Users & Auth), as "Mobile and desktop applications". Open ITAM at that same address.
AADSTS7000218 The app expects a client secret Register the address under "Mobile and desktop applications" with "Allow public client flows" = Yes, or create a secret and paste its value into ITAM.
AADSTS7000215 The client secret was not accepted Paste the secret's Value (shown only when created), not its Secret ID; check it has not expired. Or remove the secret in ITAM and use "Mobile and desktop applications".
AADSTS700016 Microsoft does not know the Application ID Check the ID. For personal accounts, the app must allow "personal Microsoft accounts".
AADSTS50020 / AADSTS50194 That kind of account is not allowed For personal accounts, set the app to "any organizational directory and personal Microsoft accounts" and use Tenant ID common. For one organisation, enter your tenant ID.
AADSTS90002 Tenant ID not valid Use common, or the exact Directory (tenant) ID.
AADSTS65001 Consent not given Sign in again and accept, or have an administrator grant consent.
AADSTS530035 Blocked by security defaults Usually a VPN making the sign-in look like it is from another country. Turn the VPN off and try again.

"This Microsoft account has not been added to ITAM" In invite-only mode, an administrator must add the address under Users & Auth → Add Microsoft Account.

Using an existing app registration broke another program Create a separate app registration for ITAM, and change the old one back.

Sign in with Google

"This Google account has not been added to ITAM" Add the address under Users & Auth → Add Google Account. Google sign-in is invite-only.

"Google did not confirm this account's e-mail address" The account's address is not verified with Google. Verify it in the Google account settings, or use another account.

Microsoft Intune

"Microsoft refused the app's sign-in" The tenant ID, client ID or secret is wrong. Copy them again from the app's Overview page, and use the secret Value.

"The app signed in, but may not read Intune devices yet" (401 or 403) - In Entra → API permissions, DeviceManagementManagedDevices.Read.All must be of type Application (not Delegated), with a green Granted tick. If it says Delegated, add it again as Application and press Grant admin consent. - A new consent can take 10–15 minutes to reach Intune. Wait, then press Save and check connection again. - The tenant needs an Intune licence (for example Microsoft 365 Business Premium).

A device is in Entra but not in Intune It was registered but not enrolled. In Intune, set Devices → Enrollment → Windows → Automatic Enrollment → MDM user scope to All. Then disconnect and reconnect the work account on the PC, or use Enroll only in device management.

The Microsoft 365 admin center says "Login is not supported for consumer users" Personal accounts (Outlook, Hotmail, Live) cannot manage Microsoft 365. Create a work account in your tenant (Entra → Users → New user), make it Global Administrator, and use it.

Google Workspace

"Google answered 403: Not Authorized" Enable the Admin SDK API and Enterprise License Manager API in your Cloud project, and connect while signed in as a Workspace super administrator.

"Google did not return a long-lived sign-in" Remove ITAM under your Google account → Security → Third-party access, then connect again.

"Not every read-only permission was approved" Connect again and tick every permission Google asks for.

"… API has not been used in project … or it is disabled" The API named in the message is not switched on in your Cloud project. Open the link in the message (or APIs & Services → Library), check the project at the top is the right one, press Enable, wait a few minutes and try again.

"Google has not allowed this service account yet" (Windows, Mac & Linux computers) The service account's Client ID is not under Domain Wide Delegation in the Admin console yet, or not with the scope https://www.googleapis.com/auth/cloud-identity.devices.readonly. The message shows the exact client ID. A new entry can take a few minutes; then choose the key file again. See Windows, Mac and Linux computers.

Creating the service-account key is blocked by an organisation policy Turn off the policy Disable service account key creation for your organisation (IAM & Admin → Organisation policies; needs the Organization Policy Administrator role). See the Setup guide.

"The scope(s) were not added because they are invalid" on the consent screen's Data Access page Expected: Google does not allow the computers scope for a normal sign-in. Use the service account instead; nothing needs adding on the consent screen.

Licences from Google have no purchase or expiry date Google does not report them. Add them yourself; see Google licences: dates.

A computer is missing from the review Google only knows computers with Endpoint Verification installed and signed in with a Workspace account (check Devices → Mobile & endpoints → Endpoints in the Admin console), and ITAM only reads them once a service account is set up (Google Workspace card → Windows, Mac & Linux computers).

Creating the Cloud project fails ("parent resource" / organisation not listed) Give your admin account Organization Administrator and Project Creator in IAM & Admin → IAM (with your organisation picked at the top), then create the project with your domain as its Location.

"Only the built-in 'admin' account can remove …" Removing a sign-in method or a device link is reserved for the built-in admin account. Sign in as admin.

Network discovery

"Discovery is dormant" or nothing is scanned Tick Turn on network scans (Settings → Network Scans).

A network cannot be added Only private ranges of /24 or smaller are allowed, for example 192.168.1.0/24. Split bigger networks into several.

"... is already in the list as ..." An address range can only be in the list once. To give that network a Windows or SNMP login, choose it in the drop-downs on the network's row.

A network says "Nothing answered: a firewall may block this PC from ..." No device on that network replied. When it is another VLAN, the router or firewall between the VLANs is usually blocking the ITAM PC: allow ping, TCP 135 and 5985, and UDP 161 from the ITAM PC's address. See Scanning other VLANs. Pupil and guest Wi-Fi are normally blocked on purpose.

A scan finds few or no devices - A VPN on the ITAM PC can send scans the wrong way. Turn it off while scanning your local network. - Phones that are asleep, or that use a private (random) Wi-Fi address, may not answer or show no maker. - MAC addresses and makers only appear for devices on the same network segment as the ITAM PC, unless the router answers SNMP (see Scanning other VLANs).

Find networks lists only the networks ITAM already knows The router did not answer SNMP. Under Switches, routers and printers (SNMP), check the router's address, add its read-only community string (or its line in the SNMPv3 file), and allow UDP 161 from the ITAM PC to it.

A device I expected was skipped With Intune or Google Workspace linked, devices they manage are left out on purpose. The scan result says how many were skipped. Untick Skip devices ... already reports (under More options) to include them.

A phone or laptop answers ping but the scan does not find it Phones save power on Wi-Fi and often miss the first ping. Keep Wake devices first on (Settings → Network Scans → More options).

A phone is found again as a new device after every scan It uses a private Wi-Fi MAC that nothing else knows. Press Same as… on it in the review and choose its asset; later scans recognise it.

Windows logins (WMI)

Use Test beside the saved login to see the exact message.

"Access denied: that PC refused this login" - In a domain, write the account as DOMAIN\account, not an e-mail address. - A Domain Admin can be refused too. Group Policy often denies them network logon on workstations, and accounts in Protected Users cannot use NTLM. Use a separate scan account. - To find the reason: on the refused PC open Event Viewer → Windows Logs → Security, find Event 4625 at that time and read Sub Status: 0xC000006A wrong password, 0xC000015B this type of logon is not allowed (Group Policy), 0xC0000064 user name not known there (the PC may not be on the domain). No 4625 event: look for an NTLM block event. - For a local account, write it as PCNAME\username, make it an administrator there, and set LocalAccountTokenFilterPolicy = 1 (see the Installation & Configuration Guide). - A Microsoft account on a PC that signs in only with Windows Hello has no password to check. Use a local scan account instead.

"The user name or password is wrong" Correct the saved login with Change, then press Test on one PC. Repeated wrong passwords can lock a domain account.

"This account is locked out" or "Windows login refused by 5 PCs, so it was not tried on … more" ITAM stopped offering the login so that it would not cause more failed logons. Unlock the account if needed, fix the cause using Test on one PC, then scan again.

"The PC accepted the connection but did not finish answering in time" Remote DCOM can be very slow on home PCs. Switch on WinRM on that PC (Enable-PSRemoting -SkipNetworkProfileCheck -Force) and add it to TrustedHosts on the ITAM PC.

"WinRM is not running on that PC, or port 5985 is blocked" Start WinRM on that PC (Enable-PSRemoting -SkipNetworkProfileCheck -Force). If you limited the WinRM firewall rule, check it allows the ITAM PC's address.

"WinRM refused the connection" Outside a domain, add the PC's IP address to TrustedHosts on the ITAM PC: Set-Item WSMan:\localhost\Client\TrustedHosts -Value "192.168.1.20" -Force

"Windows Management is blocked on that PC" Allow "Windows Management Instrumentation (DCOM-In)" in that PC's firewall.

"Neither Windows Management (135) nor WinRM (5985) answers on that PC" The PC is off, is not Windows, or its firewall blocks both. Allow one of them.

SNMP and SNMPv3

A NAS or printer shows no SNMP details Switch SNMP on in the device's settings. Then add its community string under Switches, routers and printers (SNMP) → Community strings, or choose an SNMP login in the SNMP drop-down on the network's row.

SNMPv3 Test messages

Message Fix
no answer: check the IP address, that SNMPv3 is switched on ... Check the address and port, that SNMPv3 is on, and that the firewall allows UDP to that port.
the device does not know that user name Check the username matches the user set up on the device.
the authentication password or authentication protocol is wrong Check auth_password and auth_protocol (MD5 / SHA ...).
no answer with encryption, but the device answers this user without it ... The encryption password or protocol is wrong; check priv_password and priv_protocol.
the device refused to answer this user at that security level ... The device needs authentication and encryption: fill in priv_protocol and priv_password.
the device does not allow that security level Use the security level the user was created with on the device.

Rows the CSV file cannot use are listed under its path, with the row number and the reason.

Schedules

A scheduled run did not happen Runs only happen while ITAM is running. A run missed while ITAM was shut down happens once, as soon as it starts again. Check the Schedule box: it shows the next run and the last result.

"Skipped: ... is not connected" or "Skipped: Agentless Discovery is switched off" Connect the integration, or switch discovery on. The schedule then works at its next run.

The bell says devices are waiting for review The run found changes it would not make on its own (a new kind of device, a changed model, a clash). Press Review in the bell.

Imports

CSV rows are refused The import lists each problem by row: for example a serial number or asset tag already used by another asset, a date that is not YYYY-MM-DD, or seats that are not a whole number. Fix those rows and import again. Rows without problems are imported anyway.

"The CSV needs a software_name column" Use the licence template from Settings → Import & Export and keep its first row.

Reference table import: "must look like 2027-12-31 or 31/12/2027" Dates must be year-month-day or day/month/year (UK). Excel set to US dates saves 12/31/2027, which is refused: change the column's format to yyyy-mm-dd before saving.

Reference table import: "too short to match safely" The model name needs at least 4 letters or digits (for example PowerEdge R750, not R7).

Backups and moving PCs

Saved passwords or keys stopped working after a restore or move They are encrypted for one Windows user on one PC. Enter them again (scan logins, client secrets, API keys, community strings), and reconnect Intune or Google Workspace.

A backup is refused It is damaged, is not an ITAM database, comes from a newer version of ITAM, or has no active administrator.

Undo a restore Restore the itam_prerestore_...db file ITAM saved just before.

Free version and licence keys

"The free version holds up to 100 assets" ITAM is free for up to 100 assets; decommissioned assets and software licences are not counted. Nothing is lost or locked at the limit: viewing, editing, exporting and backups keep working, only adding assets stops (by hand, imports, scans and bringing a decommissioned asset back). Imports add the rows that fit and list the rest; devices from a scan that were not added stay in the review list. Enter a licence key in About, or decommission assets you no longer use.

"Microsoft Intune and Google Workspace device imports are part of ITAM Pro" The Intune and Google Workspace links (and their schedules) need a Pro, Education or Education Trust key. If the key ends, the links stay saved and the assets they added stay; only new imports pause.

The licence key is refused Copy the whole key, starting with ITAM1., or press Open key file and choose the .itamkey file. A key with any character changed is refused. A key that has ended cannot be entered: ask CJW Apps for a new one.

The licence has ended The day after its end date ITAM is the free version again. Nothing is deleted: enter the new key in About and everything comes back at once.

I was signed out while working ITAM signs everybody out after 30 minutes without mouse or keyboard use. An administrator can change the time, or choose Never, in Settings → Server & Access → Automatic sign-out.

I have to sign in every time I reopen the window ITAM keeps you signed in when its window is closed and opened again, until the automatic sign-out time has passed. ITAM's own window uses its own Edge profile, apart from your normal browsing, so your browser's settings and extensions do not affect it. If you open ITAM in a normal browser tab instead and are asked to sign in every time, that browser is deleting ITAM's sign-in when it closes: in Microsoft Edge open Settings → Privacy, search and services → Clear browsing data on close → Cookies and other site data, and under Do not clear add http://127.0.0.1.

ITAM looks different in a browser tab (always dark, grey icons) A browser extension such as a dark-mode or colour changer is restyling the page. ITAM's own window (from the Start menu or the icon near the clock) has no extensions, so use that, or turn the extension off for 127.0.0.1. ITAM has its own Light, Dark and System themes at the top of the screen.

I closed the window: is ITAM still running? Yes. Look for the ITAM icon near the clock (it may be under the ^ arrow). Click it to open the window again, or right-click it and choose Quit ITAM to stop the program.

Will I lose my data if I delete ITAM's folder? Yes: the database and (unless you chose another folder) the backups are in that folder. Before removing ITAM or moving to another PC, open Settings → Backups & Storage, set a backup folder elsewhere (Documents or a network drive) and make a full backup; on the new installation, restore it. Updates (extracting the new zip over the folder) keep your data.

Getting help

Open About CJW-Apps ITAM (left menu) and press the Support link, or e-mail cjw-apps@cwink.com. Please include: - the ITAM version (shown in About); - what you did and the exact message (from Recent messages under the bell); - the last lines of itam.log. Remove anything private first; ITAM never writes passwords to it.
