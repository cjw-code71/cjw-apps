Installation & Configuration Guide

CJW-Apps ITAM · Version 2.7.0 · For administrators

This guide covers installing ITAM, connecting it to your network and services, and every setting an administrator looks after. New to ITAM? Start with the Getting Started guide.

Everything in this guide is done in Settings (the cog in the top bar), by an account with the Administrator role unless it says otherwise. Set up only the parts you need.

System requirements

Item Requirement
Operating system Windows 10 version 1809 or later, Windows 11, or Windows Server 2019 / 2022 / 2025 (64-bit)
Browser Microsoft Edge (included with Windows) or Google Chrome, for ITAM's own window. Colleagues can use any current browser
Processor and memory Any PC that runs Windows 10 or 11 well; 4 GB of memory or more
Disk About 200 MB for the program, plus your database and backups (a few MB for most organisations)
Account A Windows administrator to install; ITAM runs as an ordinary user
Network Only for the features you use: see Network ports and protocols
Microsoft Intune (optional) A Microsoft 365 tenant with Intune, such as Microsoft 365 Business Premium
Google Workspace (optional) A Google Workspace edition with device management

Which PC to install on. For one person, their own PC is fine. If colleagues will use ITAM, choose a PC that stays switched on and signed in (an office server or an always-on desktop): ITAM runs while that Windows user is signed in, and others connect to it with their browser.

Installing and updating

Installing

  1. Install CJW-Apps ITAM from the Microsoft Store.
  2. Start it from the Start menu, and sign in as described in Getting Started.
  • Updates arrive through the Microsoft Store and keep your data.
  • Free and Pro. Free for up to 200 assets; ITAM Pro has no limit (see Free version and Pro).
  • Uninstalling removes the data kept in the app's own storage, including backups left in the default folder. Keep backups in a folder of your own (Backups).

Moving to another PC

  1. On the old PC: Settings → Backups & Storage → Create Full Database Backup, then Download it.
  2. On the new PC: install ITAM from the Microsoft Store, sign in, then Upload Backup File... and Restore....
  3. Enter saved passwords and keys again (they are encrypted for one Windows user on one PC).

Starting ITAM with Windows

To have ITAM start when you sign in: press Windows + R, type shell:startup and press Enter. Then open the Start menu, find CJW-Apps ITAM under All apps, and drag it into that folder.

Free version and Pro

ITAM is free for up to 200 active assets (software licences and decommissioned assets do not count). ITAM Pro removes the limit: £44.99 a month or £454.99 a year, with a 30-day free trial, paid through the Microsoft Store.

  • A banner appears from 180 assets. Only the built-in admin account can Upgrade to Pro, Cancel Pro (in About) or Recover purchase.
  • Without Pro nothing is deleted or locked: viewing, editing, exporting and backups all work; only adding new assets pauses.
  • ITAM checks Pro with the Microsoft Store. If the Store cannot be reached, Pro carries on for 7 days, then shows Pro (offline) and counts down 7 more days. After 14 days ITAM works as the free version until the Store answers again; press Recover purchase in About once the PC is online.

Network ports and protocols

Use this chapter to set up firewalls, proxies and web filters. Only open what you use: a single-PC installation that does not scan the network needs nothing opened at all.

Overview

Connection Direction Needed for
ITAM's own window Inside this PC only Always (no firewall change)
Colleagues' browsers → ITAM Inbound to the ITAM PC Network access only
ITAM → devices on your network Outbound from the ITAM PC Network discovery only
ITAM → Microsoft and Google Outbound to the internet Sign-in with Microsoft or Google, Intune, Google Workspace, the Microsoft Store

Inbound to the ITAM PC

Port Protocol Used for Notes
TCP 5050 HTTP ITAM's own window on this PC Bound to 127.0.0.1 only: other computers cannot reach it, so no firewall rule is needed. Changeable in Settings → Server & Access
TCP 5443 HTTPS (TLS 1.2 / 1.3) Colleagues opening ITAM in their browser Only when Who can open ITAM is set to 0.0.0.0. Allow it in Windows Defender Firewall on the ITAM PC, ideally for your office network only. Changeable in Settings → Server & Access

Windows usually asks the first time ITAM listens on the network. Choose Private networks only. To add the rule yourself (an administrator's PowerShell):

New-NetFirewallRule -DisplayName "CJW-Apps ITAM (HTTPS)" -Direction Inbound -Protocol TCP -LocalPort 5443 -Action Allow -Profile Domain,Private

Network access is always encrypted: ITAM never offers plain HTTP to other computers. See Network access and HTTPS for the certificate.

Outbound from the ITAM PC to your devices (network discovery)

A scan only sends what is needed to recognise a device. Without saved logins it reads nothing private: it checks which ports answer and reads public banners. Open these from the ITAM PC to the networks it scans, on any firewall between them.

Port Protocol Used for Login needed
— ICMP echo (ping) Finding which addresses are in use No
— ARP MAC addresses on the same network segment (used by Windows automatically) No
TCP 5985 WinRM (HTTP, Kerberos / NTLM encrypted) Windows make, model, serial number and OS (tried first) Windows login
TCP 135 + TCP 49152–65535 WMI over DCOM / RPC The same Windows details, when WinRM is not available Windows login
TCP 135, 445, 3389, 5985 TCP connect only Recognising a Windows PC from its open ports No
TCP 22 SSH Reading the SSH banner of Linux, macOS and network devices (ITAM does not log in) No
UDP 161 SNMP v1 / v2c / v3 Name, description, make and model of switches, routers, printers, NAS and UPS units SNMP community or SNMPv3 user
UDP 5353 mDNS (Bonjour) Names of Apple devices, phones and printers No
TCP 80, 443 TCP connect only Recognising devices with a web interface No
TCP 1433, 1521, 3306, 5432, 6379, 27017 TCP connect, plus a harmless greeting Recognising SQL Server, Oracle, MySQL, PostgreSQL, Redis and MongoDB servers and their versions No

On Windows PCs that ITAM should read, allow these built-in Windows Defender Firewall rules for the ITAM PC's address (Group Policy is easiest for many PCs):

  • Windows Remote Management (HTTP-In): for WinRM, the faster method.
  • Windows Management Instrumentation (DCOM-In) and (WMI-In): for WMI over DCOM.

Use a dedicated scan account with the least rights it needs, not a domain administrator: see Windows logins (WMI).

Across VLANs and VPNs, routers do not pass MAC addresses or Bonjour, so devices on another VLAN show no MAC address. For the fullest results, run ITAM on a PC in the same VLAN, or scan from one PC per site.

Outbound to the internet (TCP 443, HTTPS)

Only needed for the services you connect. Allow these names through your proxy or web filter. ITAM sends nothing to CJW Apps.

Service Addresses Used for
Sign in with Microsoft login.microsoftonline.com Microsoft account sign-in to ITAM
Microsoft Intune login.microsoftonline.com, graph.microsoft.com Reading the devices Intune manages (read-only)
Sign in with Google accounts.google.com, oauth2.googleapis.com, www.googleapis.com Google account sign-in to ITAM
Google Workspace accounts.google.com, oauth2.googleapis.com, admin.googleapis.com, cloudidentity.googleapis.com, licensing.googleapis.com Reading devices and licence counts (read-only)
Microsoft Store The Microsoft Store service, as for any Store app Checking ITAM Pro

What is never used

  • No agent is installed on any device, and ITAM opens no remote shell or remote desktop.
  • SSH and database ports are only checked, never logged in to.
  • Only private address ranges (10.x, 172.16–31.x, 192.168.x, 169.254.x) can be scanned, each network a /24 or smaller.
  • While Enable Agentless Network Discovery is off, ITAM sends nothing on your network.

Where ITAM keeps its data

ITAM keeps its data in %LOCALAPPDATA%\CJW-Apps-ITAM, inside the app's own storage. The folder holds the database (itam_local.db), the log file (itam.log) and the default backups folder. Settings → Backups & Storage shows the database's exact path and size.

Passwords and keys you save in ITAM (client secrets, scan logins, API keys) are encrypted with Windows. They only work for the same Windows user on the same PC. If you move the database to another PC, enter them again.

Network access and HTTPS

Settings → Server & Access

Settings: Server & Access

Choose who can open ITAM with the two buttons:

  • 127.0.0.1 – this PC only (default): only this PC can open ITAM.
  • 0.0.0.0 – other computers on your network: other computers can open ITAM in a browser, always over HTTPS (encrypted) on the network port. Allow that port through Windows Firewall on this PC (Windows usually asks the first time). This PC's own window stays on http://127.0.0.1, which never leaves the PC.
  • Port for this PC: 1024 to 65535, default 5050. If it is taken, ITAM picks the next free port.
  • Network port (HTTPS): default 5443, only used with 0.0.0.0. It must differ from the port for this PC.

You do not type this PC's own IP address here: 0.0.0.0 already covers it, and a fixed address would stop ITAM starting if the PC's address changed. (An older copy with an address saved starts on 127.0.0.1 and says so in itam.log.)

Opening ITAM from other computers (on the same tab) lists the addresses to give people, each with a Copy button, for example https://192.168.1.20:5443, and this PC's name, such as https://OFFICE-PC:5443. The name keeps working if the IP address changes; otherwise ask your network administrator to reserve this PC's address. Addresses marked VPN or virtual adapter only work for computers on that VPN or on this PC. If network access could not start (for example the network port is taken), the tab says why in red.

Certificate. HTTPS needs a certificate; the tab shows the one in use, with its SHA-256 fingerprint. - Made by ITAM (default). ITAM makes a certificate for this PC's name and addresses the first time network access starts, and renews it by itself before it runs out or when the PC's name or addresses change. As no authority vouches for it, browsers warn the first time ("Your connection isn't private"): check the fingerprint matches the one in Settings, then continue. To stop the warning, press Download certificate (.crt) and install it on the other PCs under Trusted Root Certification Authorities (by hand, or by Group Policy for many PCs). - Company certificate. If your company has a certificate for this PC (from your own certificate authority or a public one), choose its PFX file (.pfx or .p12, exported with its private key), type its password and press Import PFX. ITAM checks it (right password, private key included, in date, made for web servers) and warns if it does not name this PC. Use ITAM's own certificate goes back. - A new or changed certificate is used after ITAM restarts. Private keys are stored encrypted and tied to this Windows user; moved to another PC, ITAM makes its own certificate again and a company certificate must be imported again. - Antivirus programs that inspect secure connections (for example Norton's Web Shield) may show their own certificate instead, so the fingerprint seen on such a PC differs. That is the antivirus, not ITAM.

Changes apply the next time ITAM starts (Settings → Power → Restart). If ITAM cannot start (for example another program has the port), it shows a message saying why.

Users and sign-in

Settings → Users & Auth

Settings: Users & Auth

There are three ways to sign in: local accounts, Microsoft and Google. You can use any of them together.

Local accounts

  1. Under Create New Local Account, enter a username, a temporary password and a role (new accounts start as Viewer), and optionally an e-mail address.
  2. The person signs in with the username (or the e-mail address) and is asked to choose their own password.
  • Reset PW gives someone a new temporary password.
  • E-mail adds, changes or removes the address they can sign in with.
  • Five wrong passwords lock a username for 15 minutes; twenty wrong attempts from one address lock that address. Lockouts are written to the change log.

Roles

Each account has one role. Change it in the user list (Settings → Users & Auth); invites for Microsoft and Google accounts take a role too.

Role Can do
Viewer (read-only) View and search assets, licences, hardware models and the dashboard; open any asset; change their own appearance settings and password.
Editor Everything a Viewer can, plus: add, edit and decommission assets and licences; CSV import and export; set hardware model dates and import the reference table; review devices from network scans (from the alert bell).
Administrator Everything an Editor can, plus: users and roles, Config CI & Taxonomy, Server & Access, Backups & Storage, network discovery (scans, networks, logins, schedules), Intune and Google, the change log, licence keys and permanent deletes.
Owner The built-in admin account: everything, plus restart, shut down and factory reset, removing Microsoft or Google sign-in or a device link, and the recovery key. It cannot be removed or demoted.
  • Buttons and tabs a role cannot use are greyed out with a lock. Hover to see which role is needed.
  • New local accounts, invites and people who sign in with Microsoft in organisation mode start as Viewer.
  • Accounts from before roles existed ("User") became Editors, so they keep what they could do.

Sign in with Microsoft

Lets people use their Microsoft account: personal (Outlook, Hotmail, Live) or work/school. They sign in on Microsoft's own page, so ITAM never sees the password, and two-step sign-in, PINs and Windows Hello work.

In the Microsoft Entra admin center (entra.microsoft.com): 1. Go to App registrations → New registration. 2. Name it, for example ITAM. 3. Under Supported account types, choose Accounts in any organizational directory and personal Microsoft accounts. Choose "this organization only" if only your company's accounts should sign in. 4. Under Redirect URI, choose Public client/native (mobile & desktop) and enter the address ITAM shows under the Microsoft section in Users & Auth (normally http://127.0.0.1:5050/auth/microsoft/callback). 5. Press Register. Then, in Authentication, set Allow public client flows to Yes and save. 6. Copy the Application (client) ID from Overview.

If you already use an app registration for something else (for example OneDrive in another program), create a separate one for ITAM, so changes for ITAM cannot affect the other program.

In ITAM (Users & Auth → Microsoft Sign-In): 1. Azure Application (Client) ID: paste the ID. 2. Directory (Tenant) ID: - common to allow personal and work accounts, or - your Directory (tenant) ID for one organisation only. 3. Client Secret: leave empty. It is only needed if you registered the address as Web instead. 4. Who may sign in: - Invite-only (default): add each person under Add Microsoft Account first. Anyone not added is refused. - One organisation: everyone in your tenant can sign in as a standard user. This needs the tenant ID, not common. 5. Press Save Microsoft OAuth.

The sign-in page now shows Sign in with Microsoft. If Microsoft refuses a sign-in, the page shows Microsoft's reason and how to fix it; see Troubleshooting.

Sign in with Google

Lets people use a Gmail or Google Workspace account. They sign in on Google's own page, and 2-step verification and passkeys work.

In the Google Cloud console (console.cloud.google.com): 1. Create a project, or use the one you made for the Google Workspace link. 2. Go to APIs & Services → OAuth consent screen. Choose Internal to allow only your Workspace, or External (and publish it) to allow Gmail accounts. 3. Go to Credentials → Create credentials → OAuth client ID, type Desktop app. No redirect address needs registering for this type. 4. Copy the client ID and client secret.

In ITAM (Users & Auth → Google Sign-In): 1. Paste the Google Client ID and Client Secret. If you set up the Google Workspace link first, these are already filled in. 2. Press Save Google Sign-In. 3. Add each person under Add Google Account (their Google e-mail address and a role). Google sign-in is invite-only: anyone not added is refused.

With an Internal consent screen, Google itself only lets accounts of your own Workspace through. When Google Workspace is connected, Add Google Account warns if you add an address outside it (for example a Gmail address): it is added, but it only works if the consent screen is External and published.

An invitation is tied to the Google account that first uses it. A later change of e-mail address on that account keeps working, and nobody else can take over the invitation.

Removing Microsoft or Google sign-in

Only the built-in admin account can do this, because everyone who signs in that way is locked out afterwards. In Users & Auth, press Clear Microsoft Sign-In or Clear Google Sign-In and confirm. The people's ITAM accounts are kept; they can sign in that way again once it is set up again. Other administrators can change the settings but cannot remove them.

Recovery key

The Master Recovery Key (shown once at the first sign-in) lets you back in if the admin password is lost: 1. On the sign-in page, press Ctrl + Shift + Alt + R, or click the logo five times quickly. 2. Enter the recovery key. 3. admin gets a one-time password, which must be changed at the next sign-in. Everyone else is signed out.

To set a new recovery key: Settings → Users & Auth → Update Recovery Key.

Backups

Settings → Backups & Storage

Settings: Backups & Storage

  1. Backup Target Directory / Location: choose a folder, ideally on another drive, a NAS or a synced folder.
  2. Automated Backup Schedule: Daily, Weekly or Monthly at a set time, plus Keep Backups (how many to keep). Backups run while ITAM is running.
  3. Create Full Database Backup makes a complete copy now (itam_dbbackup_<date>_<time>.db). It holds everything (assets, licences, users, settings, logins) and is safe to make while ITAM is in use.

Full backups contain password hashes and encrypted logins: keep them as private as the database.

  • Export Backup to Location writes a CSV of the assets only. It is handy for spreadsheets, but it cannot bring back users, settings or licences.
  • Restoring: press Restore... beside a full backup, check the summary, enter your password and type RESTORE. ITAM first saves the current data as itam_prerestore_...db (restore that to undo), then signs everyone out.
  • Moving to another PC: Download a full backup here, then on the other PC use Upload Backup File... and Restore.... Re-enter saved passwords and keys afterwards.

Company name, CI types and dashboard groups

Settings → Config CI & Taxonomy

Settings: Config CI & Taxonomy

  • Company name and picture: shown at the top of the dashboard for everyone. Use PNG, JPEG, GIF or WebP, up to 300 KB; a small square works best.
  • Dropdown lists (CI types, statuses, environments, locations, departments): add values here or with + Add New on any form. Remove a value with its x. One value always stays in each list.
  • Dashboard groups: each CI type belongs to Servers & Computers, Network Devices, Databases or Software Licence. A new type asks for its group; change it later with the small list beside each type.
  • Sample data: Load Sample Data and Remove Sample Data (removes only demo items you have not changed).

Software licences

Settings → Software Licences (SAM), or Add Software Licence in the left menu.

Settings: Software Licences

For each licence, record the title, publisher, version, seats, cost per seat, purchase date, expiry date and notes, and these:

  • Licensed per: what one seat is: Device, User (for example Microsoft 365), Processor core (for example Windows Server), Concurrent users or Site / unlimited. Only per-device licences are compared with the installs ITAM finds; per-user, per-core and concurrent licences show Not measured (check their seats in the publisher's portal), and a site licence is always Compliant.
  • Billed: Monthly, Yearly, Every 2 years or Every 3 years. The cost per seat is per billing period, so 10 seats at £10 billed monthly is £1,200 a year.
  • Auto-renews: the supplier renews it unless it is cancelled.
  • Licence key: hidden as dots. In a saved licence, administrators press the eye to show it; each look is recorded in the change log. Keys are never sent to other users' screens or exported. Editing a licence without touching the key keeps it.
  • Supplier / Reseller, PO / Invoice No., Agreement / Contract No. and Owner / Cost Centre, for audits and finance.

  • Installed on: the assets the licence is installed on. Type part of an asset name and choose it from the list (or + Add all shown). Compliance counts these against the seats; decommissioned assets use no seat.

  • One-time purchase (no expiry): tick it for software you pay for once (a perpetual licence). The expiry date and Needs renewing are switched off; the licence stays Active and never raises a warning. Untick it to give the licence an expiry date again.

  • Needs renewing (ticked by default; only used when there is an expiry date): the licence shows amber from a month before it expires and red in its last week. Once the date has passed it becomes Expired. The alert bell and the menu count show these.

  • Discontinued: for a licence you no longer renew. It clears its warnings.
  • Currency: chosen at the top of the licence screen. Until then, the PC's regional setting is used.
  • Spend at the top of the licence screen:
  • Subscriptions / Year: every current subscription per year (monthly ones × 12). Discontinued ones are left out, and so are Expired ones until they are renewed with a new expiry date.
  • One-off Purchases (with the year): one-time purchases bought this calendar year. Older ones are not counted.
  • Many at once: Settings → Import & Export has a licence CSV template, export and import. See the User guide.
  • Google Workspace licences come in with their seat count only; add the dates yourself. See Google licences: dates.

Agentless network discovery

ITAM can scan your own networks and find devices without installing anything on them. Settings → Discovery (Agentless)

Settings: Discovery

1. Switch it on

Tick Enable Agentless Network Discovery. While it is off, ITAM sends nothing on the network.

2. Add your networks

Under Available Networks, press + Add Subnet Block and enter: - a name; - the network in CIDR form, for example 192.168.1.0/24; - a default location and environment; - optionally a Target Credential Profile (a saved login, see below).

Rules that keep scans safe: - Only private ranges (10.x, 172.16–31.x, 192.168.x, 169.254.x) can be scanned. - Each network is a /24 (256 addresses) or smaller. Split bigger networks into several.

One login of each type per network. A network can use one Windows login, one SNMP profile and one SSH profile at the same time. To add another type, add the same CIDR again with that login, and it is attached to the existing network. Each login shows as a badge on the network; the × on a badge takes it off.

3. What a scan finds

  • Every device that answers: IP address, MAC address and maker (from the MAC address).
  • Bonjour / mDNS: Apple devices, printers and Chromecasts report their names and models.
  • Windows PCs and servers: recognised from their open ports. With a Windows login, ITAM also reads the real name, make, model, serial number and operating system. The PC running ITAM is always read this way, without a login.
  • Linux, NAS and network gear: the SSH banner, and SNMP details (with a community string or SNMPv3 login). NAS boxes (TerraMaster, Synology, QNAP and others) are recognised and filed as Storage.
  • Database servers: SQL Server, Oracle, MySQL/MariaDB, PostgreSQL, Redis and MongoDB, recognised from their ports and, where possible, a harmless greeting. ITAM never logs in to a database.

Found devices are staged. Nothing goes into the inventory until an administrator reviews it (see the User guide), unless Auto-Sync or a schedule adds the clearly safe ones.

Options

  • Auto-Sync Discovered Hosts to ITAM: after each scan, adds new devices whose CI type, make and model are already in your inventory. Anything unfamiliar waits for review.
  • Skip Devices Managed by Microsoft Intune / Google Workspace (on by default): when Intune or Google Workspace is linked, devices it manages are left alone, matched by MAC address (and by computer name). The same PC is not reported twice or sent a Windows login. MAC addresses you linked to such a device with Same as… (see the User guide) count too. The network list shows how many were skipped, for example "Completed (10 found, 1 skipped: managed by Google Workspace)".
  • Wake Devices First (on by default): before the detailed scan, every address is pinged at once. Phones and laptops saving power on Wi-Fi often miss the first ping; this wakes them so they are found first time. It adds a few seconds per network. Devices that still miss the quick check get one slower ping as well.

Windows logins (WMI)

ITAM reads Windows details over WinRM (fast) or WMI/DCOM (slower, can take a minute) using a saved login. Save one under Targeted Credential Vaults → Add Credential Profile, type WMI. Use Test to try it on one PC before scanning; Change replaces the password later.

In a company domain: create a separate scan account

Do not scan with a Domain Admin or your own account. A scan offers the login to the Windows devices that answer on the network, including any that should not be there. Many domains also block Domain Admins from logging on to workstations, so the scan would be refused anyway.

  1. Create a domain account just for ITAM, for example svc-itam-scan, with a long unique password. Do not add it to Domain Admins.
  2. Give it access on the PCs and servers to be read, using Group Policy. Either: - Simplest: add it to the local Administrators group; or - Fewer rights: add it to Distributed COM Users and give it Enable Account and Remote Enable on the WMI namespace Root\CIMv2. Check this with Test, as some details may need more rights.
  3. Check Group Policy lets it log on over the network ("Deny access to this computer from the network" must not apply to it).
  4. Save it in ITAM as DOMAIN\svc-itam-scan. An e-mail style name, such as the one used for Microsoft 365, is less reliable: that is a different identity if the domain is not synchronised with it.
  5. Press Test on one PC before scanning a whole subnet.
  6. Allow the traffic: see Ports and firewalls. Tell your security team before the first scan, as a scan looks like a port scan and login attempts to their tools.

How ITAM protects the account - If 5 PCs in a row refuse the login, the scan stops using it for the rest of that network. A locked-out account stops at once. The network list says so, for example "Windows login refused by 5 PCs, so it was not tried on 23 more". Failed logons can count towards your lockout policy, so fix the cause before scanning again. - Where a PC's DNS name points back to its address, ITAM connects by name, which allows Kerberos. Otherwise it uses the IP address, which uses NTLM and can be refused where NTLM is restricted or the account is in Protected Users.

Home or workgroup PCs (no domain) On each PC to be read, in an admin PowerShell:

net user itamscan * /add                       # asks for the password without showing it
net localgroup administrators itamscan /add
New-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name LocalAccountTokenFilterPolicy -Value 1 -PropertyType DWord -Force
Enable-PSRemoting -SkipNetworkProfileCheck -Force

On the PC that runs ITAM, in an admin PowerShell:

Start-Service WinRM
Set-Item WSMan:\localhost\Client\TrustedHosts -Value "192.168.1.20" -Force   # the PC's IP; several: comma-separated

In ITAM, save the login with the username PCNAME\itamscan (the name hostname prints on that PC), then press Test.

Keep it secure. A scan login is an administrator login, so treat it like one: - Give the scan account a long password you use nowhere else. - Limit WinRM on each PC to the ITAM computer only (run on each PC, using the ITAM PC's IP): powershell Get-NetFirewallRule -Name "WINRM-HTTP-In-TCP*" | Set-NetFirewallRule -RemoteAddress 192.168.1.220 - In a domain, prefer a domain scan account. The registry change above is then not needed. - If you only need a device list (not serial numbers and models), skip Windows logins altogether, or use Intune instead, which needs no network logins.

Microsoft accounts and Windows Hello. A PC that signs in only with Windows Hello (PIN, face or fingerprint) has no password ITAM can use. Windows Hello cannot be used over the network. Use a local scan account as above.

Ports and firewalls

The ports a scan uses, and the Windows firewall rules to allow, are listed in Network ports and protocols.

Scanning across VLANs. Routers do not pass on MAC addresses, so a device on another VLAN shows no MAC: no make from its MAC, no Same as… button, and the skip switch can only match it by name. Bonjour usually stays within one VLAN too. For the fullest results, run the scan from a PC on that VLAN.

SNMP (v1/v2c)

For printers, NAS boxes and simple network gear. - SNMP v1/v2c community strings: type up to 10, one per line. A scan tries the network's SNMP profile first, then these, then public. They are stored encrypted. - Or save an SNMP credential profile and attach it to a network.

Switch SNMP on in the device's own settings, preferably read-only and with a community other than public.

SNMPv3 network devices

For switches, routers and firewalls that use SNMPv3 (username plus authentication and encryption passwords). 1. In SNMPv3 network devices, type the full path of a CSV file (for example D:\ITAM\snmpv3.csv) and press Save. Create starter file writes an example there. 2. Add one row per device. The columns are ip_address, username, auth_protocol, auth_password, priv_protocol, priv_password, port, context, name. - Only ip_address and username are required. - Authentication: MD5 or SHA (SHA224–SHA512). Encryption: DES, 3DES or AES128/192/256. - With passwords but no protocols, ITAM uses SHA + AES128. 3. ITAM reads the file at every scan. Test beside a device asks it now and explains any failure.

Use a read-only SNMPv3 user; ITAM only ever reads. The CSV holds passwords in plain text, so keep it in a folder only administrators can open.

Schedules

Discovery, Intune and Google Workspace each have a Schedule box: - Off, every 1, 2, 4, 6 or 12 hours from a chosen time, daily at a time, or weekly on a day at a time. - Run now starts a run straight away. The box shows the next run and the last result.

What a scheduled run does by itself: - Discovery: scans every active network and adds the clearly new devices (known type, make and model). - Intune / Google: adds new devices of a known type, make and model, and updates existing ones when their type, make and model stay the same. These updates keep the tag, department, location, environment and rack you set in ITAM.

Everything else waits for review, and the alert bell says so, for example "Microsoft Intune: 3 devices waiting for review". Runs happen while ITAM is running; a run missed while it was shut down happens once when it starts again. Every run is written to the change log.

Microsoft Intune

Settings: Integrations

Brings in the devices Intune manages (Windows, Mac, iPhone, iPad, Android). The link is read-only; nothing is changed in Microsoft. Settings → Integrations → Microsoft Intune

You need a Microsoft 365 tenant with Intune (for example Microsoft 365 Business Premium) and a Global Administrator account in it.

In the Entra admin center, using an app registration (the one you use for Microsoft sign-in is fine): 1. Go to API permissions → Add a permission → Microsoft Graph → Application permissions, and tick DeviceManagementManagedDevices.Read.All. It must be Application, not Delegated. 2. Press Grant admin consent for . The row should show a green "Granted" tick. 3. Go to Certificates & secrets → New client secret, and copy the Value straight away. It is shown only once; the Secret ID will not work. 4. From Overview, copy the Directory (tenant) ID and Application (client) ID.

In ITAM: 1. Paste the tenant ID, client ID and secret value. 2. Press Save and check connection. ITAM checks with Microsoft at once and shows its message if something is wrong.

If Microsoft sign-in is still empty, ITAM fills it in with the same app registration and tells you which redirect address to add.

Then: - Review Intune devices shows what would be added or changed before anything is saved. - Set a Schedule to keep the inventory up to date.

Client secrets expire (often after 6–24 months): create a new one in Entra and save it in ITAM before then.

When a device is in more than one source (for example Intune and Google Workspace), it stays one asset. Imports match on the device's ID from that source, then its serial number, then a known MAC address, then its name.

The first time two different names are joined on a serial number or MAC address, or a device matches an asset from another source by name only, the review shows a warning and a scheduled run leaves it for you. Commit it once if they are the same device: from then on its device ID matches it automatically.

Where sources disagree, the order is Intune, then Google Workspace, then a network scan: a lower source only fills in fields that are empty. Details you set in ITAM (asset tag, department, environment, location, rack) are kept, and a blank value never erases a saved one.

Only the built-in admin account can remove the Intune link (Remove Intune link / Disconnect and forget). Assets already imported stay.

Google Workspace

Brings in Chromebooks, managed phones and tablets, Windows/Mac/Linux computers and licence seat counts from Google Workspace. The link is read-only; nothing is changed in Google. Settings → Integrations → Google Workspace

You need a Google Workspace account with super administrator rights, on a domain you have verified in the Google Admin console. Gmail does not need to be switched on for the domain.

In the Google Cloud console (console.cloud.google.com), signed in as the Workspace super administrator: 1. Create a project, for example ITAM. Under Location, choose your Workspace organisation (your domain), not "No organisation".

If your domain is not offered, open IAM & Admin → IAM, pick your organisation at the top, and give your admin account the roles Organization Administrator and Project Creator. Wait a minute and try again. 2. Under APIs & Services → Library, enable: - Admin SDK API (devices), - Enterprise License Manager API (licence seats), - Cloud Identity API (only for Windows, Mac and Linux computers). 3. Under OAuth consent screen (Google Auth Platform), press Get started and choose Internal. 4. Under Clients (or Credentials → Create credentials → OAuth client ID), create a client of type Desktop app. Copy the Client ID and Client secret, or press Download JSON to keep them. Google may show the secret only once. If you lose it, open the client and press Add secret to make a new one.

In ITAM (open on the same PC, at http://127.0.0.1): 1. Paste the client ID and secret and press Save client. 2. Press Connect Google Workspace and approve the read-only access as the super administrator.

ITAM also fills in Sign in with Google with the same client if that is still empty, and adds the Google account you approved the link with as an ITAM administrator (a Workspace super administrator already controls the devices). If that account is already in ITAM, it is left as it is. Everyone else must be added under Add Google Account.

Then: - Review devices from Google shows the devices before anything is saved. Tick which kinds to bring in: Chrome OS devices, mobile devices and, once allowed, Windows, Mac & Linux computers. - Phones and tablets are named like the Admin console: the owner's full name and the model, for example "Colin Wink's SM-S928B". Only when two devices would get the same name is the end of the serial number added. - When Google leaves out the maker, ITAM works it out from the model code (SM- → Samsung, Pixel → Google, XQ- → Sony, moto → Motorola, iPhone/iPad → Apple). - Computers that report the motherboard's placeholder text ("System Product Name") get no model; computers with no name, serial number, model or maker at all (usually browser sign-ins on a PC already listed) are left out, and the review says how many. - ITAM remembers each device's Google ID on the asset. A later review or scheduled run matches the device on that ID first, so a renamed device (for example when its owner's name changes) updates the asset instead of adding a second one. Intune devices work the same way. - Review licence seats shows the seats assigned per Google licence and adds or updates them under Software Licences. See Google licences: dates below. - Set a Schedule to keep it up to date.

Windows, Mac and Linux computers

Google knows a computer when the person installs Endpoint Verification on it (a Chrome extension and helper app) and signs in with their Workspace account. It then appears in the Admin console under Devices → Mobile & endpoints → Endpoints.

Google only gives this list to a service account that the Workspace administrator has allowed ("domain-wide delegation"); a normal sign-in is refused. The service account acts for the administrator who connected Google Workspace, and ITAM only uses it to read the computer list. This part is optional: Chrome OS, phones and licences work without it.

In the Google Cloud console (same project): 1. Make sure the Cloud Identity API is enabled. 2. Go to IAM & Admin → Service accounts → Create service account. Name it, for example itam-computers. It needs no roles: press Done. 3. Open it, go to Keys → Add key → Create new key → JSON. A key file downloads. Keep it private: it works like a password for the service account.

If Google says key creation is blocked by an organisation policy, open IAM & Admin → Organisation policies with your organisation picked at the top, find Disable service account key creation, press Manage policy, choose Override parent's policy and set it to Off, then save. Your account needs the Organization Policy Administrator role for this (add it under IAM like the other roles). 4. On the service account's Details tab, copy its Client ID (also called OAuth 2 Client ID or Unique ID: a long number).

In the Google Admin console (admin.google.com): 1. Go to Security → Access and data control → API controls → Manage Domain Wide Delegation → Add new. 2. Paste the Client ID and the scope https://www.googleapis.com/auth/cloud-identity.devices.readonly (ITAM shows it on the card to copy), then press Authorise.

In ITAM (Google Workspace card → Windows, Mac & Linux computers): 1. Press Choose key file (JSON) and pick the downloaded file. ITAM keeps it encrypted and checks it with Google straight away: it says how many computers Google lists, or exactly what is still missing. 2. The Windows, Mac & Linux computers tick box then appears next to the other device types.

A new delegation entry can take a few minutes to work; if the first check says the service account is not allowed yet, wait and choose the key file again. Only the built-in admin can remove the service account. Delete the downloaded key file once ITAM has it, or keep it somewhere only administrators can open.

Google licences: dates

Google only reports which licence each user has, so ITAM records the number of seats assigned. Google does not report the purchase date, the renewal or expiry date, or how many seats were bought, so these stay empty.

To add them: 1. In the Google Admin console, open Billing → Subscriptions and your plan (for example Business Starter). It shows the start date and when the plan or trial ends. 2. In ITAM, open Settings → Software Licences (SAM) and press Edit on the Google licence (for example "Google Workspace - Google Workspace Business Starter"). 3. Enter the purchase date and expiry date, tick Needs renewing to be warned before it ends, and save.

Review licence seats later only updates the seat count and the note. The dates you entered are kept.

Removing the link

Only the built-in admin account sees Disconnect and forget. It removes the saved sign-in and the client details; assets and licences already imported stay. It does not remove Sign in with Google: to remove that too, use Clear Google Sign-In in Users & Auth.

Hardware models and lifecycle

Settings → Hardware & Logs → Hardware Models lists every make and model with its release, end-of-life and end-of-support dates. Every asset of a model shows that model's dates.

  • Dates come from a built-in table of approximate dates. Nothing is sent anywhere. Unknown models show as Unknown; ITAM never invents dates.
  • Set dates (editors and administrators) enters a model's dates yourself; they always win over the table. For a new product the release date alone is enough: it shows as Supported until you add an end-of-life or end-of-support date.
  • Keeping the reference table up to date: Export Reference Table (CSV) saves the whole table (built-in entries and yours; the source column says which). Add models or correct dates in Excel, then Import Reference Table (CSV) (editors and administrators): ITAM shows what it would add, update or leave alone, and which rows have problems, before anything is saved.
  • Dates can be 2027-12-31 or 31/12/2027 (as Excel saves them in the UK). A blank cell keeps the date the table already has. Each row needs at least one date, in order: release, end of life, end of support.
  • Your entries are kept with your data, so updates of ITAM never remove them, and they win over the built-in entry for the same model. Their Source shows Reference table (your entry).
  • The model name must be at least 4 letters or digits, and it matches whole words, as the built-in entries do.

Restart, shut down and factory reset

Only the built-in admin account sees Shutdown/Reset in the top bar (Settings → Power): - Restart: applies network and port changes. Nothing is lost. - Shut down: stops ITAM for everyone. Backups and schedules stop until it is started again. - Reset to factory settings: erases all data and returns ITAM to first-run. It needs the recovery key and typing RESET. A full backup is made first.
